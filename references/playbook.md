# 治理与审查手册

## 1. 最小状态，不制造新的残留

先复用已有任务系统。没有等效入口时，项目最多新建一个 `.ai/state.md` 和一个
`.ai/artifacts.json`；这不是要求每个仓库必须有这些文件。
每个实验使用项目既有 manifest/跟踪系统记录，PR 只链接最终摘要与证据，不复制整份日志。

状态入口可直接使用这五项：目标；当前已验证结论；进行中的唯一假设；阻塞；下一步。
只记录决策与证据指针，不逐步转录思考、聊天或工具输出。
会话结束前复用更新，避免 daily-plan、plan-v3 和 review-final 等平行文档。

## 2. 生命周期与保留

推荐流程：active → closed/superseded/failed/abandoned → 到期核验 → 批准隔离 → 恢复验证 → 再批准清除。
`status` 与 `pinned/running/reproducible` 是不同维度，不能用一个 expired 标签替代全部判断。
没有 owner、显式到期、可再生证据或明确依赖信息时，不给删除许可。

| 类别 | 建议起点（可调整，非自动规则） | 必须保留的例外 |
| --- | --- | --- |
| 临时推理/草稿/重复计划 | 任务关闭后 7 天再复核 | 尚未落地的决策、未关闭工作 |
| 可再生日志与调试输出 | 关闭后 14 天再复核 | 安全事件、未知错误、失败现场 |
| 失败实验中间产物 | 关闭后 30 天再复核 | 唯一反例、异常回归或不可再生环境 |
| 可再生缓存/中间数据 | 关闭后 30–90 天复核 | 活跃消费者、成本高到不可接受 |
| 基线/最佳/发布模型、原始数据、最终证据 | 不设置自动过期 | 变更须项目负责人单独批准 |

`expires_at` 根据已确认的关闭时点和保留政策生成，不能用文件 mtime 推算。
依赖边方向为“消费者 depends_on 生产者”。保留消费者必须传递保留全部生产者。
保留证据指针时，也必须保证实际对象仍存在、校验可验证、访问权限有效；仅有 URL 不等于可恢复。

账本只登记文件，不接受目录递归删除、glob、绝对路径、`..` 或远程 URI。
`artifact_roots` 是候选允许范围，`protected_paths` 只能在内建保护范围上增加保护。
v1.1 隔离候选还要求 `closed_at`、`reproduce_command`、`reviewed_at`、`references_checked: true`
和 64 位小写十六进制 `content_sha256`。复核不得早于关闭、晚于审计时刻或超过 7 天；
到期不得早于关闭。`superseded_by` 可记录结论承接位置。
复核需确认本地/远程运行、代码/配置、PR/报告与对象消费者，不是运行命令后自动打勾。
工具不会执行记录中的命令，也不会验证复核声明真实。`example: true` 的账本所有项保持保留。

只对通过其他资格检查的普通文件读取内容：单件至多 1 MiB，总计至多 32 MiB；
超出预算保持 `KEEP`，交给人工或已有大产物管理系统，不用不完整哈希放行。
哈希变化将使该节点及其传递依赖保留。Git 索引与 HEAD 中跟踪的文件都受保护。
子模块、嵌套仓库、符号链接、硬链接及内建保护路径不能作为普通候选。

`--scope runs --scope plans` 只审计选定目录；先确认目录存在且可信。
范围外登记项会保留并继续保护依赖，不因为缩小扫描而失去引用约束。
扫描默认最多 20,000 个非排除文件，目录与文件条目另设 4 倍上限；达到上限返回错误，
不把截断报告当作全量盘点。大型数据仍由项目原有数据治理工具管理。

## 3. 人工隔离协议（本版没有自动执行器）

先得到精确路径审批，并冻结逐文件清单及其 SHA-256；不要接受目录通配审批。
检查原路径及每个父目录无符号链接，源是单链接普通文件，内容未变化，任务已经结束，
无生产读取者，且不是模型/数据/证据保护对象；任一未知则停止。

隔离区建议使用项目已批准且 Git 忽略的 `.quarantine/<approval-id>/`，保留原相对路径。
禁止覆盖目标；优先同文件系统移动，不做“复制成功但原件未核对就删除”的跨盘操作。
隔离记录保存审批人、时间、原因、原/新位置、大小、hash、restore_until。
停止向同一旧路径写入的任务，必要时由维护者停写；工具本身不能保证并发安全。

恢复：检查隔离件 hash、目标父路径和目标不存在，按原相对路径恢复，再核验消费者。
若原路径已有新文件，停止，不覆盖；由负责人决定合并或替代路径。
最终清除要在保留期后再次批准并检查依赖。隔离移动本身不释放磁盘空间。
Git 跟踪文件用独立分支/PR 审核移除，保留历史；不把 Git 历史重写作为常规清理。
远端对象、DVC/MLflow/LFS 等存储继续使用项目已有管理流程，脚本不访问或删除远端数据。

## 4. 算法优化的可审查分解

以“数学与接口不变量”为锚点，而不是仅按文件夹拆 PR。
每个改动回答：瓶颈证据是什么？假设如何被证伪？哪些行为变了？哪些保证没变？
测试怎样覆盖边界与负例？收益用哪些原始记录支持？怎样撤销而不丢失状态？

推荐层次：
1. 契约与正确性基线：形状、单位、坐标系、边界、梯度、数值误差、确定性范围。
2. 纯结构重构：行为不变用差分或黄金用例证明；不得掺入“顺便优化”。
3. 单项算法/数据表达变化：复杂度、收敛、误差或损失函数变化需要单独论证。
4. 运行时优化：向量化、批处理、缓存、混合精度、编译/kernel 各自列开关和回滚。
5. 集成与产物整理：验证开关组合、消费者与兼容性，清理不要混在算法提交里。

审查范围必须固定 SHA。`diff base...head` 的 merge-base 范围用于看分支引入的变化，
并不代表工作区所有修改；工作区另查。已重排的提交可另用 `git range-diff` 人工核对，
但未经授权不重写用户分支。
脚本按扩展名给的 group_hint 不能识别损失函数、统计假设或语义回归，仍需读实际代码。

## 5. 公平对比、消融和未知项

数据集/切分与协议用不可变指纹，不只写“latest”。固定环境、设备、精度、batch、预算，
列出唯一允许改变的因素。训练、验证、测试角色保持清楚，禁止测试集调参。
保存每个 seed 的真实结果、命令与原始记录指针，不能只给挑出的最好一次。
测时说明 warm-up、设备同步、缓存冷热、I/O、并发与统计单位；报告关键切片和尾延迟。
种子相同只是可复现的一部分；不同版本、设备及非确定性算子仍可能造成差异。[4]

A+B 的最终收益不能证明 A/B 单独有效：先列 baseline、A、B、A+B。
对更多维度优先高风险交互与核心单项实验，并注明未覆盖组合；不隐含要求完整 2^n 实验。
没有跑过的格子写“未验证”，不可用估计值或示例填充。

v1.1 要求每个运行增加 `training_budget`、`measurement`、`pairing_unit`、`command`、
`raw_results`、`config_sha256` 和 `dirty_patch_sha256`。后者必须显式给出，干净运行写 null。
配置哈希可以因预先声明的算法因素而不同；预算、测量方案与配对单位必须相同。
`raw_results` 是已有证据位置，不会被工具访问；必须由审查者核对存在、权限和内容。
缺少溯源字段但数值满足时返回 `UNVERIFIED_PROVENANCE`，不能伪装完整证据。

配对 gate 以相同 seed 顺序下的每对独立运行摘要为输入，默认至少 5 对（可调整，最低 2）。
它报告均值、样本标准差、配对变化离散度，检查显式相对/绝对门槛。
`max_regression_*` 控制均值退化，默认还约束每一对；`min_improvement_*` 约束平均收益。
同时给绝对和相对门槛时，两者都必须满足。相对收益分母为 `abs(baseline_mean)`；
分母为零拒绝计算百分比，改用预注册的绝对门槛。higher/lower 决定收益方向。

这不是统计显著性检验，也不验证日志真伪。可合并还需要与实验设计相符的置信区间/分布审查、
正确性测试、回归切片、交互证据、资源护栏与回滚演练。
精度或硬件本身为干预变量时，脚本会返回 INCOMPARABLE；人工记录受控对比，不能改写输入假装同条件。

## 6. 机器可检查的审查地图

同一份指标 JSON 增加 `changes` 和 `ablations`，不用多建一个 manifest。
`review --input <evidence> --root <repo> --base <sha> --head <sha> --format markdown`
将声明结构核对后输出到终端；默认输出 JSON。证据保存在项目既有追踪系统或审查范围外的
可信位置，避免工具为了生成报告新增未跟踪文件。不能通过全盘 ignore 隐藏真实工作区变化。

每个 `changes` 项包含：

| 字段 | 约束 |
| --- | --- |
| `id` | 唯一的小写字母/数字/连字符 ID，最长 64 字符 |
| `kind` | contract/refactor/algorithm/runtime/data/evaluation/hygiene/docs |
| `files` | 非空精确路径列表；必须覆盖固定 diff，不能引用范围外路径 |
| `hypothesis` | 非空、可证伪的改动目的 |
| `invariants` | 非空契约/不变量列表 |
| `tests` | command、status、evidence；缺少通过声明即报告缺口 |
| `rollback` | 可操作的撤销和恢复步骤，不只写“可回滚” |
| `depends_on` | 可选逻辑依赖 ID 列表，未知或循环依赖拒绝 |

脚本按依赖给出阅读顺序，但无法判断依赖是否被遗漏，或修改是否被错误标为 docs/refactor。
`algorithm/runtime/data` 类型视作实验因素。基线、每个单项、全组合是最小覆盖要求；
`required_interactions` 可指定额外高风险组合。对不可能独立执行的因素保留缺口并说明限制，
不虚构独立效果；必要时重新定义有实际含义的因素单元。

`ablations` 每行含 `factors`（基线为空列表）、`status`、完整 `commit`、`evidence`。
只有 `status: measured` 且格式完整才记为已声明覆盖；基线/全组合 SHA 必须分别匹配 base/head。
这不读取消融结果，也不检查其中每个数值，必须人工验证单项结果、实验上下文和交互归因。
相同组合重复、未知因素或无效高风险组合都拒绝。更多维度不自动要求全部 2^n 格子。

`review` 不接受“代码 SHA + 未提交 patch”的实验当作仅提交范围的最终证据：
先提交真实代码再重测，或保留缺口交人工审查，不移除 patch 哈希假装一致。
base 比共同祖先更新、范围为空、未提交工作、映射缺失、测试/消融/回滚缺失都会暴露。

### 退出码与结论

| 命令 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| audit | AUDIT_COMPLETE，仅盘点成功 | 不使用 | 示例或输入/扫描错误 |
| diff | 固定范围盘点成功，仍可能有 dirty/split 警告 | 不使用 | 范围或输入错误 |
| gate | NUMERIC_PASS，仅算术与字段检查 | GATE_FAIL | 不可比、证据不足、溯源缺失、示例或输入错误 |
| review | CHECKS_PASS，仅结构与数值检查 | 不使用 | NEEDS_REVIEW、EXAMPLE_ONLY 或输入错误 |

非零时必须读具体缺口，不能一概解释为算法失败。任何 0 都不是授权删除或批准合并。
示例始终不是实测；非有限数值、重复 JSON 键和非法路径拒绝。JSON 输入限制 8 MiB。
Markdown 会转义输入文本，避免证据字段被渲染成不可信 HTML/链接；仍需审查文本内容。
Git 调用禁用外部 diff、textconv、fsmonitor 和仓库定位环境覆盖；Git 与本地配置仍属于
信任边界，本程序不是恶意仓库或并发文件系统的沙箱。不要在不可信配置中执行。

## 7. 一份 PR 审查包模板

直接填入 PR body 或项目现有评审记录，不新建多个副本：

```text
目标 / 非目标：
基线 SHA / 候选 SHA / dirty patch hash：
瓶颈证据与单项假设：
不变量与行为变化：
逻辑改动地图：改动 -> 文件/符号 -> 测试 -> 证据 -> 回滚
建议阅读顺序与重点行：
实验上下文：数据/切分/协议/环境/硬件/精度/batch/预算/种子
结果：主指标 + 资源/精度护栏 + 逐运行摘要 + 原始证据位置
消融：baseline / A / B / A+B / 未覆盖组合
产物：保留 / 合并 / 待隔离；审批与恢复指针
风险与未验证事项：
回滚：commit/开关/配置/数据兼容性/执行与核验步骤
结论：可继续审查 / 请求改动 / 证据不足；待人工决定项
```
